Documentation de l'API WaveOn IoT  
 
Vue d'ensemble  
La plateforme WaveOn IoT expose une API REST destinée à la supervision et au pilotage 
d'infrastructures connectées. Elle s'adresse aussi bien aux intégrateurs souhaitant développer 
des interfaces de monitoring qu'aux systèmes automatisés ayant besoin d'acc éder aux données 
de terrain en temps réel.  
• URL de base :  https://iot.waveon.tn/WS_WAVEON/  
Rq :pour les MetaData (N etwork info, user  info, Device info.. etc) 
• URL de Base pour la base de donnée NoSQl  : 
https://iot.waveon.tn/WS_WAVEON/ proxy/:81  
Toutes les requêtes sont de type POST et doivent inclure dans leur corps les trois paramètres 
d'authentification id_client , id_user  et token . 
 Un timeout global de 30 secondes est appliqué à chaque requête ; au -delà, le serveur retourne 
une erreur 504.  
Concernant le stockage des données, une optimisation est en place : si la valeur reçue est 
identique à la dernière valeur enregistrée, elle n'est pas stockée. Une nouvelle entrée n'est 
donc créée que lorsqu'une variation est détectée .

2. Gestion des réseaux — /getNetworksInfoService/  
Un client peut posséder plusieurs réseaux associés à son compte (par exemple : bâtiment 1, 
bâtiment 2, maison, etc.).

Les équipements d’un réseau peuvent être organisés en pièces ( Rooms ), permettant une 
structuration logique et hiérarchique.

identifiants d'authentification ainsi que des timestamps de dernière mise à jour, qui permettent

Chaque Smart Controller est identifié de manière unique par trois paramètres :  unicast  
(adresse unique dans le réseau mesh, ex : 66000, 66001), Serial  Number  (sn) (numéro de 
série physique de l’équipement) et  idSmartController  (identifiant numérique dans la 
base de données).   
Parmi les champs aussi  : productName  et productId  indiquent le type de l'appareil ; 
name  est le nom lisible attribué par l'utilisateur ; enabled  indique si l'appareil est actif.  
 
On a deux types de SmartControllers  : 
Le SmartMeter (productId: 12 ) est un compteur électrique qui mesure des grandeurs 
telles que la puissance, la tension, le courant, le facteur de puissance et les énergies actives, 
réactives et apparentes. Le Gprs Flow Meter (productId: 13 ) est un débitmètre qui 
mesure le débit instantané ( flow_rate  en L/min) et le débit total cumulé ( total_flow  
en litres).  
Le Champ meterConfig: Ce champ JSON embarqué décrit la configuration de mesure 
propre à chaque SmartController. Il précise, pour chaque grandeur physique mesurée, l'unité 
(unit ), le facteur d'échelle ( scale ) et le décalage  (offset ) à appliquer pour convertir la 
valeur brute reçue en valeur réelle.  
Les grandeurs standards comme la puissance, la tension, le courant ou la fréquence sont 
disponibles par défaut.  
Il contient un tableau var qui liste spécifiquement les variables d’énergie disponibles sur cet 
équipement (par exemple : t ae, tre, tpf). De plus, si le compteur dispose d’une puissance 
maximale, celle -ci est indiquée via le champ max_power_capacity dans le meterConfig.

{

fichier de configuration réseau au format JSON, téléchargeable via ce service. Post URL  : 
https://iot.waveon.tn/WS_WAVEON/ downloadMultiNetworkFile / 
Request Body :  
{

provisioners  (utilisateurs gestionnaires du réseau), ainsi que la liste complète des nœuds 
(nodes ) et des groupes ( groups ).

Chaque nœud est identifiable via son unicastAddress  (adresse unique dans le réseau 
mesh), son UUID  (identifiant global), et son name  (nom lisible). Il peut contenir plusieurs 
elements , chacun représentant un canal indépendant de l'appareil, avec ses propres 
models  de communication mesh.  
1. Node  
Un Node  représente un équipement complet dans le réseau.  
Il possède une adresse principale (unicastAddress)  et contient un ou plusieurs Elements . 
Exemple :  
{ 
  "name": "Salle Serveur" , 
  "unicastAddress": "001F" , 
  "elements": [...]  
} 
Caractéristiques principales :  
• Un Node  correspond à un appareil physique unique.  
• Il possède une adresse principale .  
• Il regroupe plusieurs Elements .  
• Chaque Node peut exposer plusieurs fonctionnalités via ses Elements et Models.  
 
2. Element  
Un Element  est une partie logique du Node.  
Chaque Element possède sa propre adresse indépendante  dérivée de l’adresse principale 
du Node.  
Exemple :  
{ 
  "name": "Element: 0x001F" , 
  "index": 0, 
  "models": [...]  
} 
Caractéristiques principales :  
• Un Node peut contenir plusieurs Elements.  
• Chaque Element correspond à une adresse indépendante .  
• Un Element regroupe un ensemble de Models .  
• Chaque Element peut représenter une partie fonctionnelle différente de l’appareil.
